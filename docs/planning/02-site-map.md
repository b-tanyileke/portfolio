## Purpose

This document defines the information architecture of the engineering website.

Rather than focusing only on navigation, it describes how visitors will discover content, understand the author's professional story, and explore engineering work.

The website is designed to grow over time while maintaining a simple and intuitive structure.

---

## Design Philosophy

Visitors should never feel lost.

Every page should answer one of three questions:

- Who is this engineer?
- What has this engineer built?
- How does this engineer think?

Navigation should always support these goals.

## Project Library

Projects are treated as engineering case studies rather than portfolio entries.

Each project should contain:

- Overview
- Problem Statement
- Motivation
- Solution
- Architecture
- Technology Stack
- Implementation
- Challenges
- Trade-offs
- Results
- Lessons Learned
- Future Improvements
- Repository
- Demo
- References

---

## Engineering Notes

Engineering Notes document continuous learning.

Topics may include:

- AI
- Machine Learning
- Computer Vision
- Retrieval-Augmented Generation
- MLOps
- Docker
- FastAPI
- GitHub
- Software Engineering
- Open Source
- Career Reflections

These notes should emphasize understanding and practical experience rather than tutorials.

---

## Open Source

The Open Source section documents community involvement.

Examples include:

- Pull Requests
- Issues
- Bug Fixes
- Documentation
- Feature Contributions
- Community Participation

The goal is to demonstrate collaboration rather than simply listing repositories.

## Contact

Visitors should be able to contact the author through:

- Email
- LinkedIn
- GitHub

Future additions may include:

- Calendly
- Professional social platforms

---

## Now

The "Now" page documents current areas of focus.

Examples include:

- Current projects
- Research interests
- Technologies being learned
- Professional goals

Unlike a blog, this page changes periodically and reflects what is actively being explored.

---

## Growth Strategy

The website is intentionally designed to expand.

New pages and sections should integrate naturally into the existing navigation without requiring major restructuring.

The architecture should remain intuitive regardless of future content growth.
